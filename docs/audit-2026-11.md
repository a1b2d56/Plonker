# Plonker audit: findings and fix plan

## Context

You asked for a deep audit of the app for bugs, code smells and improvements. Three read-only sweeps covered (1) playback, audio, downloads and recognition, (2) data, network, security and build, (3) UI, view models, TV and Wear. They reported 72 findings. I re-read the code behind the ones marked **✔** below and they are as described; the rest are reported by the sweeps and I will confirm each before touching it.

Not covered by the audit: most of `AudioCache`, `CrossfadeController`, `QualityUpgrade`, `bitperfect/*`, `cast/*`, the lyrics providers, the settings screens, `DetailScreen`, `NowPlayingScreen`, most TV screens, and the `backend/` and `web/` folders.

Nothing was changed. Below: the findings by priority, then the fixes I propose to make, in batches that are each verified and committed separately on `feat/sing-recognition-history` (as per the standing brief: branding, namespace and signing untouched, tests stay green).

### F. Code health

- **Size**: `BitChordApp` composable ≈3,580 lines in a 4,334-line `MainActivity.kt`; `CrossfadeController.kt` 4,307; `NowPlayingScreen.kt` 3,922; `MainViewModel.kt` 3,730; `AppSettings.kt` 2,617; `PlaybackService.kt` 2,507.
- **Duplication**: `tv/build.gradle.kts` copies most of the app's (with its own hardcoded `versionCode`); HLS/DASH download helpers; duration formatting in four places; the two playlist stores' hand-written JSON.
- **Swallowed errors**: ~15 empty `catch` blocks in `LibraryBrowser.kt`; `runCatching` around suspend calls swallowing cancellation (`LyricsRepository`, `KizzyRPC`, `Backup`, `SpotifyImporter`, `VersionSwitcher`).
- **Tests missing** for everything that holds user data: `LocalPlaylistStore`, `OfflinePlaylists`, `Backup`, `ListeningStats`, `Downloads.record`, `SponsorBlockApi`, the Shazam queue, `SessionCallback`, `MainViewModel` concurrency.
- **CI**: release workflow signs on every push to main without running tests; `:shared`/`:sharedUi` `jvmTest` and TV tests never run in CI; secrets interpolated straight into shell.
- **Dependencies**: `security-crypto 1.1.0-alpha06` (deprecated), mixed `kotlinx-serialization-json` 1.7.3 / 1.11.0, coroutines-guava 1.9.0 beside core 1.10.2, JitPack deps without verification metadata.
- **Localisation**: TV UI and recognition sheet hardcoded English; several view-model strings and missing plurals.

## Fix plan (as approved)

Five batches, one commit each (some split further), in this order. Everything else above stays a recorded finding.

### Batch 1 — privacy and backup (A1, A2, A3, A7)
- Move the three tokens out of `bitchord_settings` into the already-excluded encrypted auth store (`EncryptedPrefs`/`AuthStore`), with a one-time migration in `AppSettings` init. Excluding the whole settings file instead would drop every setting from backup.
- `backup_rules.xml` + `data_extraction_rules.xml`: add excludes for `app_webview/` (domain `root`), `files/downloads/` and `files/offline-hls/`. The recognition history database stays in the backup.
- `PlaybackService.SponsorBlockCoordinator`: only query for 11-character YouTube ids (reuse the existing id check if one exists; otherwise a small `isYouTubeVideoId` helper with tests).

### Batch 2 — data loss (B1, B2, B3, B9, B10)
- `LocalPlaylistStore`, `OfflinePlaylists`: parse per entry (skip a bad one, keep the rest); if the stored blob is wholly unreadable, keep the raw string under a `_corrupt` key and refuse to overwrite it; guard mutations with a lock. Extract the parse/encode into pure functions and unit-test them.
- `Downloads.record`: take `recordLock` around update + encode + submit.
- `Downloader`: when a `Range` header was sent, require 206 (200 only for a whole-file request).
- `DownloadStore`: trim the stem by UTF-8 bytes on a code-point boundary; sanitise the `videoId` fallback. Tests for CJK and surrogate pairs.

### Batch 3 — playback threading (C1, C2, C3, C4, C13)
- `SessionCallback.onPlaybackResumption`: read the player on `Dispatchers.Main`, then do the library fallback on IO.
- `SponsorBlockCoordinator`: keep the fetch `Job`, cancel it on transition, apply results on Main; key `SponsorBlockApi`'s cache by id + categories.
- `MainViewModel` Spotify loader: `_detailStack.update { }` for every write (also the other `value = value.map` sites in the file).
- `LibraryBrowser.paginate`: offset by the requested page size, cap only the length. Extend the existing paginate tests.

### Batch 4 — recognition (D1, D2, D3, D6)
- `MusicRecognitionService`: publish the permission error to `_recognitionStatus`; stop the recorder by cancelling and letting the recording coroutine release it in `finally`.
- `RecognitionSheet`: an error view with a "Grant microphone" action; no double start after a grant; strings to resources.
- `MainActivity`: "Play Now" plays through the same path the history sheet uses (`TabActions.playRadio` when Shazam gave a video id, first search hit otherwise); "Add to Queue" queues instead of playing. I will confirm the queue entry point in `TabActions` before wiring.

### Batch 5 — small correctness fixes (E1, E4, E6, E10, E11)
- `JamInviteLink`: accept both `plonker` and `bitchord` schemes (+ test).
- `openMoodGenre`: cancel the previous job and check the selection before applying.
- Playlist edits: show the existing failure message instead of `onFailure = {}`.
- `verifyDevInstall`: use the real dev application id in app and TV.
- Remove the always-true conditions, guard the `floorMod` divisor, delete dead `sourceResults` and the orphaned KDoc.

### Deliberately left for a decision
- **TV sign-in server (A4-A6)**: needs a design choice (pairing code + bind to LAN address + remove the dead remote endpoints) and TV hardware to test.
- **B4-B8, C5-C12, D4-D5, E2-E3, E5, E7-E9, E12**: real, but each needs device testing or a behaviour decision.
- **Section F**: refactors, CI and dependency changes.
